The exact meanings depend on the project’s pipeline configuration, but visually:

Green checkmark



Plain Text

The stage or job completed successfully.

Gray skipped symbol



Plain Text
⏭
A job or stage was skipped, likely because its rule or condition did not apply.

For example:

Deployment runs only on a release branch
A frontend job runs only when frontend files change
Production deployment requires a manual action
A job does not run for scheduled dependency scans
Orange exclamation mark



Plain Text
!
This generally indicates a warning or a job allowed to fail without failing the complete pipeline.

9. What are “Clear runner caches” and “New pipeline”?
At the top-right, the page contains:

Clear runner caches
GitLab runners may cache downloaded dependencies or build files to speed up future pipelines.

Clearing the cache forces subsequent jobs to retrieve or recreate those files. This may be necessary if stale or corrupted cached content is causing incorrect builds.

New pipeline
This starts a pipeline manually, normally after choosing a branch and potentially supplying permitted variables.

It does not necessarily create or change code. It tells GitLab to execute the pipeline against the selected code version.
