# PulseTMS `gold_unified_long` — Tableau Calculated Field Reference

Every calc field below is written against `sdi_vw_dashboardPulseTms_gold_unified_long`. Copy the
formula text directly into Tableau's calculated field editor — field names on the left match
what you'd see in the field list once created.

## Conventions used throughout

- **Naming**: `c.[Metric Name] [Value Type]` — metric name first so Tableau's alphabetical field
  list clusters everything for one metric together, matching the convention you already started.
- **`ATTR()` everywhere in the weekly-tier fields below — no `SUM`, no `AVG`.**
  `gold_unified_long`'s grain is `(data_source, qgp_date, lob, channel_group, metric_name,
  metric_type)` with no duplicates, so with `qgp_date` on columns and `lob`/`channel_group`
  either on the view or filtered to one value (which every `IF` filter below already assumes),
  each cell corresponds to exactly one row. `ATTR()` just extracts that value directly — no
  aggregation happening, none needed. It's also *safer* than `SUM`/`AVG` here: if a worksheet
  ever ends up with more than one row per cell (channel_group left unfiltered, say), `SUM`/`AVG`
  would silently compute a plausible-looking wrong number, while `ATTR()` shows `*` — a visible
  signal something's mis-filtered, not a quiet wrong answer.
- **`SUM`/`AVG` only reappear in the QTD Tiles section**, and there they're genuinely needed —
  a QTD tile deliberately spans *multiple* `qgp_date` rows collapsed into one number, which is
  real aggregation, not a single-row extraction. `SUM` for additive metrics, `AVG` for
  UPV-family (unique-visitor counts, which can't be summed without double-counting across
  weeks). Don't swap those to `ATTR()` — that would break the QTD tiles, showing `*` instead of
  a real total.
- **`AvT` vs `AvF`**: `AvT` (Actual vs. Target) used for QGP, matching its own "Target"
  language. `AvF` (Actual vs. Forecast) used for MFC and the Adobe/UPV Forecast cross-reference.
- **`[channel_group] = "All Channels"`**: for any channel-grain source (Adobe, MFC, Platform,
  Biddable) where you want one combined number rather than a per-channel breakdown, filter to
  this instead of re-aggregating channels yourself in Tableau — it's already computed correctly
  in SQL, with its own correct WoW/YoY.
- **`[data_source] = "MFC_SPEND_CHANNEL"`**: always include this on MFC fields, not just
  `metric_name`. MFC contributes two full row sets (Channel + Granular) for the same spend —
  omitting the `data_source` filter silently doubles your numbers.
- **⚠ Two QGP metrics have no Target, ever**: `digitalPctNoAssistanceActivations` and
  `digitalPctAssistanceActivations` are confirmed to have zero `QGP_TARGET` rows — not missing
  data, absent by design. Their AvT% fields are omitted below rather than built to always
  return null.
- **Adobe has no Target/Forecast of its own** — `metric_type = 'ADOBE_VOLUME'` is the only
  type Adobe ever has. The one exception is `upvTotalAdobe`, which has a real forecast
  counterpart in the separate `UPV_FORECAST` data_source — that's the one Adobe metric that
  gets a full AvF family below; the other 17 get Actual + WoW% + YoY% only.
- **YoY fields are given singly, not Pos/Neg split.** If you want the split, it's the identical
  pattern as WoW's Pos/Neg fields below — swap `wow_pct` for `yoy_pct`.

## QGP (`data_source = "QGP_SCORECARD"`)

### Activations BOPIS (`activationsBopis`)

```
c.Activations BOPIS Actual
ATTR(IF [metric_name] = "activationsBopis" AND [metric_type] = "QGP_ACTUAL" THEN [metric_value] END)

c.Activations BOPIS Target
ATTR(IF [metric_name] = "activationsBopis" AND [metric_type] = "QGP_TARGET" THEN [metric_value] END)

c.Activations BOPIS AvT %
([c.Activations BOPIS Actual] - [c.Activations BOPIS Target]) / ABS([c.Activations BOPIS Target])

c.Activations BOPIS AvT % (Pos)
IF [c.Activations BOPIS AvT %] > 0 THEN [c.Activations BOPIS AvT %] END

c.Activations BOPIS AvT % (Neg)
IF [c.Activations BOPIS AvT %] < 0 THEN [c.Activations BOPIS AvT %] END

c.Activations BOPIS YoY %
ATTR(IF [metric_name] = "activationsBopis" AND [metric_type] = "QGP_ACTUAL" THEN [yoy_pct] END)
```

## QTD Tiles

The pattern: same filters as the weekly Actual field, plus **quarter scope** and the
**`max_date` guardrail** — so the aggregate stops exactly at the last week with real actuals,
not at the end of the calendar quarter (which would pull in `NULL` forecast-only future weeks).

```
c.Current Quarter
[p.Quarter] = [qgp_quarter]
```

(You already have this — reused below via `[c.Current Quarter]`.)

### Worked example — SUM family (Store Traffic)

```
c.Store Traffic Actuals QTD
SUM(
  IF [metric_name] = "storeTraffic"
     AND [metric_type] = "QGP_ACTUAL"
     AND [c.Current Quarter]
     AND [qgp_date] <= [max_date]
  THEN [metric_value]
  END
)

c.Store Traffic Target QTD
SUM(
  IF [metric_name] = "storeTraffic"
     AND [metric_type] = "QGP_TARGET"
     AND [c.Current Quarter]
     AND [qgp_date] <= [max_date]
  THEN [metric_value]
  END
)
```

### Worked example — AVG family (UPV Total Adobe)

```
c.UPV Total Adobe Actuals QTD
AVG(
  IF [metric_name] = "upvTotalAdobe"
     AND [data_source] = "ADOBE"
     AND [c.Current Quarter]
     AND [qgp_date] <= [max_date]
  THEN [metric_value]
  END
)

c.UPV Total Adobe Forecast QTD
AVG(
  IF [metric_name] = "upvForecast"
     AND [data_source] = "UPV_FORECAST"
     AND [c.Current Quarter]
     AND [qgp_date] <= [max_date]
  THEN [metric_value]
  END
)
```

### Worked example — MFC (remember the `data_source` filter)

```
c.MFC Spend Actual QTD
SUM(
  IF [metric_name] = "mfcSpendActual"
     AND [data_source] = "MFC_SPEND_CHANNEL"
     AND [c.Current Quarter]
     AND [qgp_date] <= [max_date]
  THEN [metric_value]
  END
)
```
